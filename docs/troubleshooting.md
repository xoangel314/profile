# Troubleshooting Notes

## 1. 页面能打开但请求没有进入本地后端

原因通常不是前端页面，而是 Gateway灰度路由。检查顺序：

1. 浏览器请求头中的版本标识。
2. Nacos实例 metadata中的版本标识。
3. Nacos注册 IP是否为当前内网网卡，而不是 VPN或旧 DHCP地址。
4. 点击发送的同一秒，本地服务是否出现 HTTP工作线程日志。

经验：只有定时任务日志不能证明请求到了本机。

## 2. 相同代码却出现数据库不存在字段

曾遇到查询 SQL包含源码实体已经删除的字段。最终排查方向是请求命中了旧实例或运行时加载旧依赖，而不是直接修改公共数据库。

验证方法：

- 对比源码、编译 class和本地依赖 JAR。
- 打印当前 PID classpath。
- 对照请求时间检查本机 HTTP日志。
- 清理旧实例并执行标准 Maven `clean compile`。

## 3. SSE 返回 HTTP 200但页面报错

SSE会先建立成功连接，再在事件数据中传输业务错误。因此需要查看 EventStream内容，不能只看状态码。

## 4. 环境变量关闭加密但登录仍失败

前端登录函数可能无条件调用加密方法，导致配置开关形同虚设。解决方式是追踪最终 Request Payload，让登录实现显式遵循环境开关，并避免硬编码第二套密钥。

## 5. VPN与动态 IP

不要永久写死开发机 IP。每次启动读取当前路由和内网地址，并在注册中心确认最终实例地址。VPN已开启也不代表 Git、浏览器和 Java进程走同一路由。
